# Совместимость с Windows и OTS

OTS Pass означает успешную структурную обработку OpenType Sanitizer, а не гарантию открытия оригинала просмотрщиком Windows. Браузерный предпросмотр использует отдельную пересобранную WOFF2-копию. Результаты этих проверок необходимо различать.

## Arial Hebrew: диагностика 2026-10-04

Оригинал `ArialHB.ttc` (SHA-256 45844259d86c0f2ea1b2446ecf34be47491b09d868f2f996672396ffe505f3f3) содержит девять TrueType-начертаний. В name отсутствуют Windows-записи семьи, полного имени, PostScript-имени и других идентификаторов, хотя соответствующие Macintosh-записи есть. В некоторых начертаниях Windows-записей нет вообще.

Проверка AddFontResourceExW с FR_PRIVATE отказала оригиналу, извлечённым TTF и OTS-копиям. Контрольный системный Arial загрузился. Временное добавление недостающих name ID 1, 2, 3, 4, 6 для platform=3, encoding=1, language=0x0409 из существующих имён позволило Windows загрузить каждое из девяти начертаний. Добавлялись только отсутствующие записи, существующие не заменялись.

Сохранена отдельная копия `data/repairs/ArialHB-windows.ttc`; она прошла OTS целиком и для всех начертаний, а также приватную загрузку Windows. Оригинал не изменён, исправленная копия автоматически не добавлена в каталог. Приватная загрузка тут же отменена; постоянной установки шрифта в Windows не было. Загрузка GDI не равнозначна проверке всех вариантов формирования текста или полного установочного сценария.

Текущий автоматический механизм восстановления реагирует на отказ OTS, поэтому этот случай не вызывает исправление. Для дальнейшего развития следует хранить диагностику совместимости отдельно от OTS и предоставлять явную операцию подготовки версии для Windows. Нельзя объявлять отсутствие таких name-записей повреждением всех шрифтов: совместимость зависит от целевой платформы.

Спецификация: https://learn.microsoft.com/en-us/typography/opentype/spec/name
