# Download formats and conversion

## User workflow

Above the style selector, an archived face has a compact download table. The
original is always available byte-for-byte, including TTC/OTC collections.
Additional rows export the currently selected face: its native TTF or OTF outline
container, WOFF and WOFF2. A button requests preparation; queued/running rows
show status. While the page remains open, completion starts the attachment download.
Returning later exposes a normal download link. An already prepared browser
WOFF2 is reused immediately. Changing style navigates to the corresponding face
and updates both preview and download options. Variation axes remain intact:
changing specimen sliders does not silently export a static instance.

TTF ↔ CFF OTF outline changes are deliberately unavailable. Renaming an extension
is not conversion. WOFF containers preserve the underlying native outline format.
Malformed fonts may analyze successfully yet fail output generation; errors stay
in the conversion queue and originals remain downloadable.

Remote pages list actual source artifacts individually, with their filenames and
formats, above the style selector. Explicit clicks download the selected artifact
through the adapter's pinned manifest and bounded transport/cache. No binary is
fetched while opening a page. ZIP artifacts remain ZIP downloads. An index update
invalidates a stale revision link with HTTP 409, preventing a silent version swap.
Downloading a source file does not import it. The existing family import action
still schedules import/analysis; conversion becomes available on archived faces.
Matching names across sources never authorize replacing a local face by remote
bytes; those files are distinct source instances until their identity is known.

## Implementation

`font_exports.py` owns format options, routes, cache keys and conversion processing.
`app.py` registers the module and runs a third OS-locked worker (`convert`). The
existing `work_queue` and `queue_control` persist its claims, pause and retries.
`/imports` exposes conversion alongside import and preview with independent control.
HTTP/status handlers perform lightweight container inspection, never compression.

Cache keys include physical face ID, target format and exporter version. Origins
share generated bytes while source-qualified downloads retain contextual names.
Requests deduplicate queued/running jobs. Missing completed cache entries can be
requested again. Failures require explicit queue retry, preventing retry storms.

The worker verifies the immutable original SHA-256, reapplies the tolerant cmap
reader, writes `.export.part`, checks output character coverage/native outline
container and flavor, then atomically publishes under the archive lock. Completion
commits in SQLite. A valid published output left before a process crash is reused
on recovery. Private partials are removed only by the conversion lock owner.
Backups include exports and relocate queue input paths on restoration.

| Endpoint | Purpose |
|---|---|
| GET `/api/fonts/<id>/exports` | Original and available format/status/size/download links |
| POST `/api/fonts/<id>/exports/<format>` | Ready link (200), durable queued work (202), unsupported (422) |
| GET `/download-export/<id>/<format>` | Ready cached attachment; never generates |
| GET `/sources/<source>/fonts/<family>/download/<index>?revision=<revision>` | One pinned source artifact |

`static/font_exports.js` renders text safely, polls readiness and handles explicit
requests. Cache files never become original catalogue instances. Source downloads
use `indexer_client.binary`, retaining its URL/download policy and size checks.

## Verification

`test_font_exports.py` checks genuine WOFF bytes, native format restrictions,
original preservation, persistent pause, request deduplication, published-file
reuse after an interrupted completion and failure/retry. `test_google_fonts.py`
checks explicit pinned source download, stale links and metadata-only page visits.

Additional tests cover exporting a selected bold face from a TTC collection,
retaining CFF outlines in WOFF, and portable export-cache/control restoration.
The running localhost service also generated and downloaded an Arial Italic
WOFF with 2,710 mapped characters; browser polling exposed its ready link without
reload, and the browser console contained no errors.

An isolated Linux Docker Compose instance additionally exercised the third worker,
queued WOFF preparation, a validated ready attachment and conversion controls.
Test containers were stopped and named volumes retained. Source style-table
downloads link directly to exact matching artifact filenames; unmatched entries
remain unavailable instead of guessing a file.

Source attachment acquisition now uses the [Download queue](Download-queue.md).
The source URL serves ready cache bytes or a waiting page referring to a durable
job; the actual transfer runs outside the HTTP request.
