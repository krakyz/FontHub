# FontHub

Self-hosted каталог шрифтов с поиском, предпросмотром, анализом Unicode и языкового покрытия Hyperglot. Python, Flask, SQLite, fontTools и Waitress. Интернет-источники подключаются отдельными адаптерами к общему HTTP-индексатору по arr-модели.

Тестовая версия для личного архива и доверенной домашней сети. Сам сайт пока не имеет авторизации. Шрифты и готовый каталог в репозиторий не входят. Открытая лицензия исходного кода пока не выбрана; см. [NOTICE](NOTICE.md).

В разделе ошибок кнопка «Исправление» открывает сравнение оригинала и отдельной
обработанной копии. Для ручного восстановления копия создаётся по запросу и повторно проверяется OTS;
сохранение требует выбора пользователя. Новые отклонённые оригиналы также проходят
автоматическое восстановление с проверкой сохранности, описанное ниже. [Описание](wiki/Repairs.md).

OTS-проверка оригиналов теперь хранится в базе и выполняется отдельной очередью.
Новые локальные файлы по умолчанию ждут успешной проверки перед анализом;
для каждого источника можно выбрать блокировку, предупреждение или пропуск.
Раздел «Карантин и ошибки» позволяет повторять задания и явно разрешать анализ.
Существующий каталог проверяется постепенно без скрытия прежних записей поиска.
Подробности: [проверка оригиналов и разрешение ошибок](wiki/Original-validation.md).

Импорт разделён на приём оригинала, полный анализ и подготовку предпросмотра.
Оригинал доступен в разделе «Импорт» сразу после приёма; в поиск шрифт попадает
после полного анализа. WOFF2 проверяется OpenType Sanitizer и переиспользуется
для скачивания. Подробности: [архитектура конвейера](wiki/Pipeline.md).

## Запуск

Нужны Python 3.12+, Git и зависимости:

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe -m pip install -r indexer/requirements.txt
./start.ps1
```

Откройте [FontHub](http://127.0.0.1:8765). Скрипт запускает локальный индексатор на порту 8766 в фоне, если не указан внешний `FONTHUB_INDEXER_URL`. Для раздельного запуска в двух терминалах:

```powershell
.venv/Scripts/python.exe -m indexer.service
.venv/Scripts/python.exe app.py
```

Альтернативный способ: `docker compose up --build -d`. Два контейнера используют отдельные тома; только порт FontHub опубликован на localhost. Настройки подключения, хранения и API-ключа описаны в [Operations](wiki/Operations.md).

## Развёртывание через Docker

Нужны Docker Engine с Compose на сервере либо запущенный Docker Desktop с Linux-контейнерами и включённой виртуализацией на Windows. Сейчас публичный образ в registry не опубликован: следующие команды собирают образы из исходного кода проекта. Команды выполняются из корня репозитория.

### Вариант 1: Docker Compose

```sh
docker compose up --build -d
docker compose ps
docker compose logs --tail=100 fonthub indexer
```

Откройте `http://127.0.0.1:8765` на компьютере, где запущен Docker. Compose собирает приложение и индексатор, ждёт готовности индексатора и хранит данные в отдельных постоянных томах `fonthub-data` и `indexer-data` (Docker добавляет к именам префикс проекта). Пересоздание контейнеров не удаляет эти тома.

Чтобы сменить порт, скопируйте `.env.example` в `.env` и измените `FONTHUB_HTTP_PORT`. Для внутреннего API индексатора можно задать одинаковый токен `FONT_INDEXER_TOKEN`: Compose передаст его обоим сервисам. `.env` исключён из Git. Токен защищает API индексатора, а не веб-страницы FontHub.

По умолчанию сайт доступен только на самом сервере. Для доступа из домашней сети замените в `compose.yaml` привязку порта на `"${FONTHUB_HTTP_PORT:-8765}:8765"`, ограничьте доступ доверенной сетью и открывайте `http://АДРЕС_СЕРВЕРА:8765`. Внешний доступ требует отдельной авторизации на reverse proxy или доступа через VPN. Порт индексатора наружу публиковать не нужно.

Загрузка шрифтов: через браузер либо копированием своей папки `fonts` в inbox контейнера:

```sh
docker compose cp ./fonts/. fonthub:/data/inbox/
```

Inbox просматривается рекурсивно. Сервис переносит принятые файлы внутри тома; локальная папка `fonts` остаётся на вашем компьютере. Для постоянной входной директории сервера можно дополнительно подключить bind mount к `/data/inbox`; эта директория должна быть доступна контейнеру на запись, поскольку успешно принятые файлы удаляются из inbox.

Обновление из новой версии исходников:

```sh
git pull
docker compose up --build -d
docker compose ps
```

Перед обновлением сделайте резервную копию. Остановка: `docker compose stop`. Удаление контейнеров без удаления томов: `docker compose down`. **Не используйте `docker compose down -v` для рабочего архива: эта команда удаляет тома с данными.**

### Вариант 2: отдельные Docker-образы без Compose

Соберите оба образа:

```sh
docker build -t fonthub:local .
docker build -t fonthub-indexer:local -f indexer/Dockerfile .
docker network create fonthub-net
docker volume create fonthub-data
docker volume create fonthub-indexer-data
```

Запустите индексатор, затем приложение. Каждая команда `docker run` ниже записана в одну строку, чтобы работать и в PowerShell, и в shell Linux:

```sh
docker run -d --name fonthub-indexer --restart unless-stopped --network fonthub-net -v fonthub-indexer-data:/data fonthub-indexer:local
docker run -d --name fonthub --restart unless-stopped --network fonthub-net -p 127.0.0.1:8765:8765 -e FONTHUB_INDEXER_URL=http://fonthub-indexer:8766 -v fonthub-data:/data fonthub:local
docker logs --tail=100 fonthub
docker logs --tail=100 fonthub-indexer
```

Откройте `http://127.0.0.1:8765`. Для доступа из домашней сети используйте `-p 8765:8765` вместо привязки к localhost с теми же ограничениями доступа, что описаны выше. Файлы можно загрузить через сайт или `docker cp ./fonts/. fonthub:/data/inbox/`.

При обновлении пересоберите образы, остановите и удалите **контейнеры**, затем повторите команды запуска с теми же томами:

```sh
docker stop fonthub fonthub-indexer
docker rm fonthub fonthub-indexer
```

Не удаляйте тома `fonthub-data` и `fonthub-indexer-data`. Эти имена отличаются от томов, созданных Compose: переключение между двумя способами не переносит архив автоматически.

### Перенос образов на домашний сервер

Если сборка выполняется на другом компьютере, экспортируйте образы и загрузите их на сервере с совместимой архитектурой:

```sh
docker save -o fonthub-images.tar fonthub:local fonthub-indexer:local
```

Перенесите файл на сервер и выполните:

```sh
docker load -i fonthub-images.tar
```

После этого используйте вариант запуска без Compose. Архив образов не содержит ваших шрифтов и базы; данные переносятся отдельной резервной копией.

### Резервные копии Docker-развёртывания

Для Compose:

```sh
docker compose exec fonthub python archive_backup.py backup --data /data --output /data/archive-backup.zip
docker compose cp fonthub:/data/archive-backup.zip ./archive-backup.zip
docker compose exec indexer python archive_backup.py backup --kind indexer --data /data --output /data/indexer-backup.zip
docker compose cp indexer:/data/indexer-backup.zip ./indexer-backup.zip
```

Без Compose используйте `docker exec fonthub ...` / `docker exec fonthub-indexer ...` и `docker cp` вместо соответствующих Compose-команд. Сохраняйте копии вне контейнерных томов. Для согласованной копии остановите поступление новых файлов и скачиваний; механизм использует SQLite backup API и проверяет контрольные суммы архивных файлов. Восстановление выполняется в новую пустую директорию — см. [Operations](wiki/Operations.md).

## Архив и источники

Загрузите шрифты через браузер или положите в `data/inbox`. Сканирование происходит каждые пять секунд. Поддерживаются TTF, OTF, WOFF, WOFF2, TTC и OTC. Для больших копируемых файлов используйте расширение `.part`, затем переименуйте после завершения копирования.

Оригиналы сохраняются в `data/originals`, проверяются по SHA-256 и удаляются из inbox после фиксации приёма и задания анализа. Ошибки приёма попадают в `data/quarantine`; ошибки анализа оставляют оригинал в архиве. Сведения появляются в поиске после полного анализа всех начертаний, до создания WOFF2. Предпросмотр готовится отдельным процессом, исходный файл не изменяется.

Раздел **«Импорт»** (`/imports`) показывает семь сохраняемых в SQLite очередей: загрузки, приём файлов, проверка OTS, восстановление, анализ, предпросмотры и конвертация. Можно приостановить каждую очередь, продолжить обработку, повторить задания с ошибками, загрузить файлы и запустить сканирование. Пауза действует после текущего задания и сохраняется при перезапуске. Inbox сканируется рекурсивно, в том числе при паузе; новые файлы ожидают продолжения. Подробная логика и API: [Import queue](wiki/Import-queue.md).

Экземпляр определяется файлом и источником. Одинаковый шрифт из локального архива и Google Fonts показывается двумя строками. Побайтно одинаковые оригиналы физически хранятся один раз, но происхождение и дата добавления сохраняются отдельно. Повторная загрузка внутри того же источника не создаёт новый экземпляр. Семейства объединяются только внутри источника; скачивание семейства не захватывает файлы других источников.

Обычная загрузка получает локальный источник. Для явного выбора используйте подпапки inbox с идентификатором источника, например `google-fonts`. Источник также можно изменить на странице шрифта; конфликт с уже существующим экземпляром не сливается автоматически. Подробности: [Import and duplicates](wiki/Import-and-duplicates.md).

## Индексатор Google Fonts

В разделе «Источники» нажмите «Обновить индекс». Независимый индексатор синхронизирует официальный Git-репозиторий, получает METADATA.pb, описания и доступные лицензии через sparse checkout. Бинарные файлы шрифтов при индексации не скачиваются. Сохраняются исходные документы, все разобранные поля, включая неизвестные, и нормализованные записи.

Снимок привязан к конкретному коммиту и публикуется целиком после проверки всех записей. Ошибка оставляет предыдущий индекс активным. Задание имеет идентификатор и сохраняемый статус; после перезапуска незавершённое задание помечается прерванным. Одновременно выполняется одно обновление, между попытками действует минимальный интервал. Автоматического расписания и скрытых повторов нет.

Поиск работает по опубликованному индексу через локальный HTTP API. Во всех областях результаты обновляются автоматически при изменении фильтров; по умолчанию выбрана область «Везде». Это поиск по сохранённым снимкам, без запросов к внешним сайтам. Обновление индекса запускается отдельно в разделе «Источники». Просмотр страницы внешнего шрифта не загружает бинарник: предпросмотр и импорт запускаются отдельными действиями. Файлы скачиваются из зафиксированного коммита и кэшируются в FontHub. Покрытие языка до анализа файла считается неизвестным, а не нулевым.

Активны адаптеры Google Fonts, Noto и открытых проектов Adobe; для них получены реальные снимки. Font Library и Font Squirrel помечены неактивными: получение полного каталога и файлов не подтверждено. Их нельзя обновить, включить или выбрать в фильтрах. Диагностические данные сохраняются. Adobe обнаруживает публичные репозитории организации, включая экспериментальные проекты; это не подписной каталог Adobe Fonts. Строка Adobe пока представляет проект репозитория. Совпадающее имя семейства скрывает внешнее предложение только внутри того же источника; сравнение версий и полноты установленного семейства пока не реализовано.

## Анализ

Языковое покрытие рассчитывается по обязательным символам основных орфографий живых языков Hyperglot с достоверностью preliminary и выше. Процент означает наличие символов, а не проверку формирования текста. Выбор отображаемых языков задаётся в настройках.

Подтаблицы cmap читаются независимо. Для повреждённого format 4 учитываются только корректные смещения и индексы глифов. Неполнота анализа отмечается на странице; соответствия не угадываются. Повторный анализ: `.venv/Scripts/python.exe app.py --reanalyze SHA256`.

## Документация и проверки

[Участие в разработке](CONTRIBUTING.md) · [Ограничения безопасности](SECURITY.md). Offline-проверки: `python scripts/checks.py`; на Windows полный набор: `.venv/Scripts/python.exe scripts/checks.py --windows`. GitHub Actions проверяет Linux, Windows и сборку Docker.

[Wiki](wiki/Home.md): архитектура, жизненный цикл индексатора, контракт API, дубликаты, эксплуатация и восстановление. Комментарии в коде объясняют границы ответственности и важные решения.

```powershell
.venv/Scripts/python.exe test_app.py
.venv/Scripts/python.exe test_indexer.py
.venv/Scripts/python.exe test_google_fonts.py
.venv/Scripts/python.exe test_adapters.py
.venv/Scripts/python.exe test_live_sources.py
.venv/Scripts/python.exe test_source_zip.py
node test_search.js
```

Тест индексатора использует локальный Git-репозиторий и проверяет сохранение снимка после ошибки. Интеграционный тест Google Fonts требует запущенного индексатора с опубликованным снимком и скачивает небольшое семейство во временный архив.

Это локальная тестовая версия: FontHub не имеет пользовательской авторизации; изоляция анализа недоверенных файлов пока не реализована. Индексатор рассчитан на один процесс синхронизации. Для резервной копии сохраняйте SQLite через backup API и оригиналы; подробности в wiki.
Страницы незагруженных сетевых семейств используют ту же двухколоночную вёрстку, что и архивные шрифты. Покрытие, Unicode и проверенные свойства явно недоступны до импорта; сведения источника и лицензии доступны сразу. Предпросмотр запускается отдельно и не заменяет анализ.

## Добавление своего адаптера

Добавьте небольшой Python-модуль в `indexer/adapters/` и перезапустите индексатор. Регистрация и появление источника в FontHub выполняются автоматически. Общая часть отвечает за запросы, задания, сохранение исходных ответов, проверку записей и публикацию снимков. Контракт, примеры, возможности источников и реальные ограничения описаны в [Adapters](wiki/Adapters.md).


В результатах поиска языковые ячейки внешних шрифтов показывают ✓ (язык заявлен
источником), ≈ (указан соответствующий набор символов) или ? (нет сведений).
✓ отображается зелёным, ≈ — жёлтым, без процентов. Фильтр языка учитывает прямые
заявления и приблизительные совпадения письменности (≈), а точный поиск по
символам — только проанализированные файлы архива.
На внешней странице языки и subsets отображаются отдельно «По данным источника».
Проверка: `.venv/Scripts/python.exe test_source_languages.py`.

Раздел «Источники» содержит сохраняемые переключатели участия интернет-источников
в поиске. Без готового индекса источник нельзя включить; он отсутствует в фильтрах.
Отключение сохраняет индекс и уже импортированные шрифты. Локальный архив и inbox
остаются включены. Проверка ссылки и получение индекса — отдельные действия.

Страница источников показывает сводку включённых источников и готовых индексов.
В таблице отдельно представлены переключатель поиска, готовность индекса,
время обновления и действия. Проверка ссылки и причины ошибок доступны через
«Диагностику». Первичное получение и обновление индекса различаются подписями
кнопок. Локальный inbox и инструкция ручного импорта вынесены в отдельный блок.


## Надёжность и производительность

Поиск архива выполняет фильтрацию, группировку, сортировку и пагинацию в SQLite.
Полный JSON читается только для семейств текущей страницы. Индексы обновляются
в одной транзакции с анализом. См. [Search](wiki/Search.md).

Импорт ведёт журнал и восстанавливается после аварийного завершения процесса.
Исходник удаляется после проверки копии и фиксации SQLite. Это не заменяет
резервные копии при отказе диска или потере питания. См. [Operations](wiki/Operations.md).

```powershell
.venv/Scripts/python.exe archive_backup.py backup --data data --output backups/archive.zip
.venv/Scripts/python.exe archive_backup.py backup --kind indexer --data data/indexer --output backups/indexer.zip
.venv/Scripts/python.exe archive_backup.py restore --input backups/archive.zip --data restored-data
.venv/Scripts/python.exe -m indexer.check examples.adapters.example_json --fixture examples/adapters/responses.json
.venv/Scripts/python.exe test_import_recovery.py
.venv/Scripts/python.exe test_import_queue.py
.venv/Scripts/python.exe test_preview_recovery.py
.venv/Scripts/python.exe test_queued_cmap.py
.venv/Scripts/python.exe test_search_sql.py
.venv/Scripts/python.exe test_backup.py
```

Восстановление допускается только в новую папку. Compose проверен сборкой,
импортом, пересозданием обоих контейнеров и восстановлением на изолированных
томах. Существующий локальный архив автоматически в Docker не переносится.

## Скачивание в выбранном формате

На странице начертания доступны оригинал и экспорт в родной TTF/OTF, WOFF и WOFF2. Недостающие файлы готовятся по нажатию через отдельную очередь конвертации и кэшируются; готовый WOFF2 предпросмотра используется повторно. Изменение контуров TTF ↔ OTF не выполняется. На сетевых страницах можно скачать конкретный файл источника без импорта. Подробности: [Font exports](wiki/Font-exports.md). Проверка: `.venv/Scripts/python.exe test_font_exports.py`.

## Очередь сетевых загрузок

Скачивание файла источника и добавление семейства в архив используют отдельную очередь «Загрузки». Она показывает байты, поддерживает паузу, отмену и повтор ошибок. Один файл скачивается однократно для обоих действий; готовый кэш доступен сразу. Импорт начинается после загрузки и может оставаться на паузе независимо от сети. Лимиты источника обрабатываются через Retry-After. Подробности: [Download queue](wiki/Download-queue.md). Проверка: `.venv/Scripts/python.exe test_download_queue.py`.

В разделе карантина доступна массовая подготовка исправлений всех отклонённых OTS файлов. Результаты видны в каталоге проверок; сохранение выбранной версии остаётся явным действием пользователя.

Новые оригиналы при блокирующей политике OTS после отказа автоматически проходят очередь восстановления. В каталог автоматически допускается только копия с OTS Pass и подтверждённой сохранностью данных. Неудачные и неоднозначные случаи попадают в карантин для ручного выбора. Оригинал и происхождение сохраняются; подробности — [wiki/Repairs.md](wiki/Repairs.md).

## Бэклог

- [ ] Добавить проверку совместимости с Windows отдельно от статуса OTS: диагностировать отсутствующие Windows-записи таблицы `name`, показывать результат и причину на странице шрифта. OTS Pass и наличие браузерного превью не считать подтверждением совместимости с Windows.
- [ ] Добавить явную операцию «Подготовить версию для Windows»: дополнять недостающие записи из существующих имён, сохранять оригинал, показывать сравнение и давать выбор версии для каталога. Проверять обработанную копию через OTS; при наличии Windows проверять загрузку без постоянной установки. Учесть работу self-hosted сервера на Linux, где нативная проверка Windows недоступна. Проверочный пример — Arial Hebrew (`ArialHB.ttc`, девять начертаний); диагностика описана в [Windows compatibility](wiki/Windows-compatibility.md).

## Перед публикацией

Проект подготовлен к размещению исходного кода: личный архив, базы, кэши, секреты и файлы шрифтов исключены из Git. Открытая лицензия пока не выбрана. Публичные Docker-образы и GitHub Releases ещё не опубликованы. Для публикации нужно создать репозиторий, подключить его remote, проверить состав коммита и отправить код; GitHub Actions запустится после отправки.

Пошаговая первоначальная отправка: [Publishing](PUBLISHING.md).
