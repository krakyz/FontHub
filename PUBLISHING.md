# Публикация исходного кода на GitHub

Подготовка не создаёт удалённый репозиторий и не отправляет файлы в GitHub. Сначала создайте пустой репозиторий в своём аккаунте (без автоматически добавленного README или LICENSE) и возьмите его URL. Владелец выбрал Apache 2.0; файл LICENSE сохраняется при публикации.

## Проверка состава

```sh
git status --short
git add .
git diff --cached --stat
git diff --cached --check
```

Проверьте, что в коммит не попали `data`, `backups`, `.venv`, `.env`, `.hyperglot-cache`, файлы шрифтов и базы. Gitignore исключает их; не используйте принудительное добавление этих путей.

## Первоначальная отправка

После проверки состава:

```sh
git commit -m "Prepare FontHub source for publication"
git branch -M main
git remote add origin URL_ВАШЕГО_РЕПОЗИТОРИЯ
git push -u origin main
```

Замените URL_ВАШЕГО_РЕПОЗИТОРИЯ настоящим HTTPS- или SSH-адресом. Если remote origin уже существует, сначала проверьте его через `git remote -v`, вместо повторного добавления.

После отправки проверьте вкладку Actions: настроены Linux- и Windows-проверки, JavaScript-проверка и сборка Docker с тестом контейнера. Эти задания до отправки в GitHub выполняются только локально. Workflow не публикует Docker-образы, не разворачивает сервис и не использует ключи доступа.

## Docker-образ

README содержит самостоятельную сборку, запуск, перенос образов и резервное копирование. Готовые образы в registry пока не опубликованы. Публикацию в GHCR или Docker Hub, владельца образов, теги и поддерживаемые архитектуры нужно настроить отдельно; примерные registry-адреса намеренно не выдаются за существующие.
